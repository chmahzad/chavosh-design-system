# 0011 — Public snapshot and identifier minimisation

**Status:** Accepted (29 Sep 2026). Supersedes the build-input location in ADR 0005 and the snapshot reference in ADR 0010 §Sources; the Button mapping itself is unchanged.

**Context.** The read-only exporter captures what the Figma Plugin API returns, including identifiers that are not needed to build tokens and should not be published: the Figma file key, the published component key and library style keys (which Figma also embeds in style IDs as `S:<key>,…`). The raw capture is integrity-locked (SHA-256), so it cannot be redacted in place without ceasing to be the capture.

**Decision.**
1. **Raw capture — private root of trust.** The file produced by the manual exporter run is kept byte-for-byte, outside this repository. Its SHA-256 and size are recorded as an attestation.
2. **Public snapshot — build input.** `build/sanitize-snapshot.mjs` derives `snapshots/figma/chavosh-button.snapshot.public.json` (schema `chavosh.figma-public-snapshot` 1.0.0, `derivedFrom` = raw schema 1.2.0). The converter accepts only this schema, so private identifiers cannot reach DTCG, CSS, React or Storybook.
3. **Deterministic, rule-based sanitisation.** The complete rule set:
   - remove `source.fileKey`, `components[].key` and `styles.*[].key`;
   - rewrite style IDs, and every style reference, to `style:<type>/<style name>`.

   Everything else must be identical, which is proven on every run: token names, values, descriptions, aliases, modes, node IDs, variable IDs and component structure. The sanitizer fails on unexpected identifier patterns, style ID collisions, unknown references, residual identifiers or any other difference.
4. **Kept identifiers.** Figma node IDs, variable IDs and collection IDs are kept for traceability (Figma Variable → token); they give no access to the file. The file name "Chavosh Financial — Design System" is kept.
5. **Provenance chain.** `chavosh-button.snapshot.public.provenance.json` (generated by the sanitizer) records:
   - the raw capture SHA-256 and size (attestation);
   - the sanitizer name and version;
   - transformation counts;
   - the public snapshot SHA-256 and size;
   - the authored capture record (method, date, extractor, roots, scope).
6. **Integrity policy.** Verification checks the PUBLIC snapshot SHA-256, size, schema, extractor and sanitizer versions, and the absence of private identifiers. When the raw capture is available (`CHAVOSH_RAW_SNAPSHOT=<path>`), verification also re-derives the public snapshot and requires byte equality plus the attested raw SHA-256. Without it, public verification passes and reports the raw capture as attested only.

**Evidence (this capture).**
- Raw capture: `adecb1cc8587634f057eb4bddb34a6a789012d65340f08cdd92dc81abe6b0a52` (490 808 bytes).
- Public snapshot: `ffe8b4c2f060dee4ec270837b702345d1f0e58ee3364cecbcbf0fcee93dca7d5` (489 291 bytes).
- Transformations: 1 file key, 1 component key and 2 style keys removed; 2 style IDs and 60 style references rewritten.
- Downstream: the 8 DTCG token sets are byte-identical to those built from the raw capture. `ch-tokens.css` differs only in its provenance header comment.

**Future direction.** A later exporter version should stop collecting these identifiers at the source: no file key (and therefore no `enablePrivatePluginApi`), no component or style keys, and public style IDs. Future captures would then need no identifier rewriting. That requires a new manual Figma capture and is not part of this decision.
